## 三、验收前 30 分钟准备（按顺序执行）

### 1. 重置演示数据库（必做）

测试脚本会创建大量 `e2e_*`、`cc*` 账号并改动轮次。重置后恢复为：1 位管理员、1 位教师、5 名学生、6 个课题、1 个开放轮次、1 条公告。

```bash
# macOS / Linux
cd student-topic-system/src
# 先按 Ctrl+C 停掉旧服务
rm -f topicgo.db topicgo.db-wal topicgo.db-shm
python app.py
# 看到 Running on http://127.0.0.1:5000 即成功
```

```powershell
# Windows PowerShell
cd student-topic-system\src
Remove-Item topicgo.db* -ErrorAction SilentlyContinue
python app.py
```

### 2. 打开四个互相隔离的浏览器会话（关键）

用两个浏览器各开「普通 + 隐私」：Chrome 普通 = `admin`、Chrome 无痕 = `teacher`、Edge 普通 = `zhangsan`、Edge InPrivate = `chenqi`。

> 不要用同一浏览器的两个无痕窗口：它们共享 Cookie，后登录的账号会把前一个顶掉。

| 窗口 | 账号 | 密码 | 用途 |

| 1 | `admin` | `123456` | 管理员登记/停用 |
| 2 | `teacher`（刘老师） | `123456` | 建轮次、题库、监控 |

## 七、30 秒电梯陈述（开场背下来）

> 我们的项目是「学生选题系统 TopicGo」，解决课设选题顺序不透明、名额易超卖、统计靠手工三个痛点。
> 系统支持先到先得、绩点优先、多志愿分配、随机抽签四种公平策略，用 `BEGIN IMMEDIATE` 事务加部分唯一索引保证多人同时抢题不超卖，退选自动递补、全程操作留痕；登录采用管理员登记制，并按导师归属过滤，只有本班师生能看到对应课题。
> 三套自动化测试 115 + 22 项断言全部通过，并发实测 6 人抢 2 个名额零超卖。
> 主体功能代码 3841 行，两人各承担 16 项任务。
