# 自测说明（tests 目录使用指南）

> 本文档说明如何使用 `tests/` 目录下的脚本对系统进行**自测**，作为系统有效性的验证证据。
> 所有脚本均为普通 Python 文件，无需额外框架，任何人均可重复执行。

---

## 一、测试前准备

```bash
# 1. 进入源码目录并安装依赖（只需一次）
cd student-topic-system/src
pip install -r requirements.txt

# 2. 启动系统（测试期间保持运行，不要关闭）
python app.py
# 看到 Running on http://127.0.0.1:5000 即成功
```

```bash
# 3. 新开一个终端，进入 src 目录（重要：脚本使用相对路径 topicgo.db）
cd student-topic-system/src
```

## 二、四个测试脚本

| 脚本 | 作用 | 规模 |
| --- | --- | --- |
| `test_concurrent_select.py` | 并发选题防超卖：6 人同时抢 2 个名额 | 3 项断言 |
| `test_regression.py` | 全功能回归：权限/策略/留痕/候补/志愿/抽签/公告/班级隔离/CSRF/新建轮次/课题开关/自助改密 | 74 项断言 |
| `test_e2e_multi_user.py` | 多用户协同：2 教师 + 12 学生、3 班级共同操作 | 22 项断言 |
| `demo_seed.py` | 生成多人演示账号（非断言，供手工协同测试） | 打印账号清单 |
| `take_screenshots.py` | 自动截取系统各页面截图（文档配图用） | 输出到 wiki/screenshots/ |

执行方式：

```bash
python ../tests/test_concurrent_select.py
python ../tests/test_regression.py
python ../tests/test_e2e_multi_user.py
python ../tests/demo_seed.py
```

> 若提示找不到 flask，也可使用虚拟环境：`.venv/bin/python ../tests/xxx.py`

## 三、如何判断结果

每个脚本逐行打印 `PASS/FAIL`，末尾输出汇总：

```
===== 结果: 74 通过, 0 失败 =====
```

- 全部 PASS → 对应功能验证通过；
- 出现 FAIL → 末尾会列出失败项，向上找到该 FAIL 行，括号中的数字即实际值，与预期值对比即可定位。

## 四、各脚本验证点（预期结果）

### 1. test_concurrent_select.py（并发防超卖）

| 验证点 | 预期 |
| --- | --- |
| 6 人并发抢上限 2 的题目 | 恰好 2 人"已确认"、4 人"候补中" |
| 已确认数 | ≤ 人数上限（不超卖） |
| 记录总数 | = 6（无人丢失） |

### 2. test_regression.py（全功能回归，74 项）

| 测试组 | 关键验证点 |
| --- | --- |
| 退选留痕 | 退选后记录保留为"已退选"，操作日志有 select/cancel 两条 |
| 候补与递补 | 满员入候补；自动/手动两种递补方式行为正确 |
| 权限管控 | 未登记账号拒绝登录；停用账号拒绝；管理员不涉及课程业务；师生越权被拦截 |
| CSRF 防护 | 缺少令牌的 POST 被拒绝；页面渲染真实隐藏域 |
| 分组轮选 | 非允许班级被拒绝，允许班级可选题 |
| 多志愿分配 | 高绩点第一志愿命中；平行志愿第二志愿命中；落空志愿作废留痕；教师可撤销误提交志愿 |
| 随机抽签 | 中签数=名额；未中签进候补；种子写入日志（可复现）；多题报名不重复中签 |
| 并发防超卖 | 6 人抢 3 名额不超卖 |
| 师生归属隔离 | 学生只看自己老师的课题；教师只看/改自己的课题；教师可自建轮次 |
| Dashboard 与公告 | 师生首页可访问；教师发公告学生首页可见；跨教师隔离 |
| 课题面向班级 | 按班级可见/不可见；越班选题被拒绝；同班可选题 |
| 课题关闭与开放 | 关闭后学生不可见；重新开放后可见 |
| 自助修改密码 | 验证原密码后修改成功；旧密码失效；管理员可重置 |

### 3. test_e2e_multi_user.py（多用户协同，22 项）

模拟 **2 位教师 + 12 名学生、3 个班级**：

| 场景 | 预期 |
| --- | --- |
| 教师发布课题 | 各自发布成功（含面向班级） |
| 并发抢课 | A 班 4 人抢上限 2 的课题：2 人确认、2 人候补 |
| 班级隔离 | B 班不能选 A 班专属课题；跨老师课题不可见不可选 |
| 退选递补 | 候补自动递补，退选记录保留 |
| 多志愿分配 | 绩点最高者命中第一志愿，无超分配 |
| 教师数据隔离 | 监控/日志只见自己的课题与学生 |
| 最终一致性 | 全部课题无超卖、无学生重复确认 |

### 4. demo_seed.py（手工协同测试）

运行后打印 2 教师 + 12 学生账号（密码均为 `123456`），**用多个浏览器（或隐私窗口）同时登录不同账号**，即可模拟师生共同操作：

- `admin`：登记用户、给学生分配老师
- `demo_t1`（王老师，管 A/B 班，先到先得）/ `demo_t2`（李老师，管 C 班，多志愿）
- `demo_s1 ~ demo_s12`：分属三个班的学生

## 五、建议自测顺序

```bash
python ../tests/demo_seed.py            # 1. 生成多人账号（可同时手工登录体验）
python ../tests/test_e2e_multi_user.py  # 2. 多师生协同自动验证
python ../tests/test_regression.py      # 3. 全功能回归
python ../tests/test_concurrent_select.py  # 4. 并发防超卖演示
```

## 六、注意事项

1. **测试会写数据**：脚本会自动创建测试账号（`e2e_a1`、`cc1`、`test99` 等）并修改轮次设置，属正常现象，不影响正式账号（`zhangsan`/`teacher`/`admin`）；
2. **恢复干净状态**：关闭服务 → 删除 `src/topicgo.db` → 重新 `python app.py`，数据库按初始种子重建；
3. **测试必须在 src 目录下执行**（脚本用相对路径 `topicgo.db` 连接数据库）；
4. 测试过程中服务控制台输出的 200/302 日志为正常请求记录。
